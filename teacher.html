This is the one dashboard for A-Level French and Spanish. Each language has two sites: 1 · Vocab (Le Lexique / El Léxico) and 2 · Site (A-Level-French-BBA / A-Level-Spanish-BBA). The KS3 & KS4 vocabulary sites are kept apart at the bottom — they are not used for A-Level teaching. Paste the codes your students send you, one per line, in any mix: the page works out which is which. Everything is decoded in this browser: nothing is uploaded, and no server ever sees a student name.

Set this week's task

Pick the language, tick what the class should do — vocabulary lists and A-Level site activities together in one link — give the task a name and a date, and copy the link. Post it where you post the site's address — Teams, the Class Notebook, an email. A student who clicks it is taken through the tasks in order, vocabulary first and then the site, with a Next button at the bottom of the screen; the task stays on their device until a newer link replaces it. Nothing to edit, nothing to upload. Choose the class and post the link in that class's own channel: the link then also tells the site which class the student is in, so nobody is asked, the code they send carries the class, and the roster below splits by it.

Import the Forms responses

In Microsoft Forms choose Open in Excel and drop the Excel file that downloads straight here — no need to save it as CSV. A CSV still works too, whichever separator and character set your Excel used. Every code in the sheet is picked up, and each one keeps the school email beside it, so one student is one row however they typed their name. Re-dropping a newer export later only adds what's new, so this is safe to repeat each half-term.

Paste codes

Accepts LEXFR2. LEXFR1. LEXES2. LEXES1. LEXKSFR2. LEXKSES2. DOSFR2. DOSFR1. DOSES2. DOSES1..

Paste the whole thing. Select the code column in the Forms summary workbook — or the whole sheet, headings, timestamps, email addresses and all — and paste it here. Codes are found wherever they sit, in any column order, so nothing needs tidying first and a weekly copy is one action. Several codes from the same student over time are welcome: the newest is shown, with the change since the previous one, and a code already in the roster is skipped rather than counted twice.

Share the roster with the department

The roster lives in this browser, so a colleague opening the dashboard sees their own. Point every teacher at the same OneDrive-synced folder and the file in it becomes the shared one. Nothing is ever overwritten: each sync reads what is there, merges it with what is here, and writes the union back, so two people working on the same afternoon combine rather than clobber. Chrome and Edge only.

Identities

Most of the time you will not need this. A file exported from the Form carries each student's school email beside their code, and that is what the roster groups on — so Toby, Toby G and (sans nom) from one address are already one student, named from the register. This box is for the leftovers: codes pasted with no email beside them, or a student who sent from two different addresses.

The same student rarely spells themselves the same way twice — ÇA, C Ackermann, CAC, 2435. The page cannot know those are one person, so you state it here. Left of the =, the identity — the candidate number where you have one. Right of it, the name you want to read in the tables, then any other spellings, separated by |.

Lines that end in the same name are one student. So writing to the first-name-and-initial convention, one line per spelling, works as you would expect: ÇA = Charbel A on one line and c Ackermann = Charbel A on the next give a single Charbel A, not two.

Class list and matching

Paste your register once: a candidate number and the name you want to read in the tables. Then every loose spelling in the roster can be attached to one of those students, which is how a name that arrived without a number gets one. Nothing is attached until you press the button at the bottom.

One student per line. Number and name in either order, separated by a tab, two spaces, a comma, a semicolon or = — so a column pair pasted straight out of a spreadsheet works.
The workbook has one sheet per site: a row per student, a column per exercise or list they have done, by name, with the score in the cell. The CSV is the same roster as one long list, one row per student per exercise — for a tracker or a mail merge.

Reading the tables

Seen — distinct items the student has met at least once, out of the whole list. Mastered — items answered correctly enough times to leave the review cycle. Leeches — items failed repeatedly; these are the ones worth teaching directly. Exam avg — mean of the in-app tests, with the number of tests in brackets. Done / Opened — dossier tiles marked finished, and tiles merely opened. Flagged hard — tiles the student marked difficult.
An amber row means seen is climbing but mastered is not — the student is browsing rather than learning, which is the pattern most worth catching early.

Codes carry aggregate statistics only — no answers, no free text. Decoded locally in this browser; no server, no upload. These are snapshots a student chose to send, not live monitoring. The roster is stored in this browser only: clearing site data, or opening the page on another machine, starts it empty — use the backup button to move it.
